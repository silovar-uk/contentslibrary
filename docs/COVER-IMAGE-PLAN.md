# 表紙画像の登録・表示 実装計画

対象コミット: `f613038` 以降。作品の表紙画像を、外部URL(Amazon画像)を参照する形で登録・表示します。

## 結論

2本のPRに分けます。**先に確認すべき前提が2つあり、どちらも実測で確定済みです。**

| PR | 内容 | 規模 |
| --- | --- | --- |
| PR-1 | CSPの緩和・保存API・表示(一覧サムネ＋詳細) | 中 |
| PR-2 | 登録のしやすさ(ISBN自動導出・URL貼り付け) | 小 |

**サーバー側のマイグレーションは不要です。** `works.metadata_json` は自由形式のJSON
(上限10,000文字、`src/routes/works.ts:93`)で、スナップショットにも既に含まれています。
表紙URLは `metadata.cover_url` に置けば、読み取り側のAPI変更なしで一覧まで届きます。

---

## 実測で判明した前提

### 前提1: 現在のCSPが外部画像を全面ブロックしている

`src/http.ts:37` の `img-src 'self' data:` が、`src/index.ts:160` で**HTML本体にも適用**されています。
ブラウザで実際にAmazonの画像を読み込ませて確認しました。

```
<img src="https://m.media-amazon.com/images/P/4062748223.09.MZZZZZZZ.jpg">
→ result: error(ブロック) / naturalWidth: 0
```

**CSPを緩めない限り、何を実装しても画像は1枚も表示されません。** これがPR-1の中心です。

### 前提2: 画像サイズの選択が「軽さ」を7倍変える

同一書籍で、Amazonのサイズ指定を変えて実測しました。

| サイズ指定 | 実測バイト数 | 60件ぶん |
| --- | --- | --- |
| `THUMBZZZ` | 2,157 B | 約126KB |
| `TZZZZZZZ` | 3,599 B | 約211KB |
| `MZZZZZZZ` | 6,333 B | 約371KB |
| `SCLZZZZZZZ` | 6,333 B | 約371KB |
| `LZZZZZZZ` | 42,864 B | **約2.5MB** |

URLの一部を変えるだけで7倍違います。**保存時にサイズ指定を正規化することが、軽さ対策の本体です。**

### 前提3(落とし穴): 表紙が無いとき404ではなく「200＋43バイトの透明GIF」が返る

```
存在しないISBN → status=200 / content-type=image/gif / 43バイト / 先頭"GIF89a"
```

**`<img>` の `onerror` は発火しません。** 「読み込み失敗」として扱えないため、
エラーイベント頼みの代替表示は動きません。読み込み完了後に `naturalWidth <= 1` を見て判定します。

### 前提4: ISBN形式のURLは「本」でしか使えない

`images/P/<ID>.09.<サイズ>.jpg` の形式を、本以外のASINで試しました。

| 対象 | ID | 結果 |
| --- | --- | --- |
| 本(ISBN-10) | `4062748223` | 6,333 B の画像 |
| 映像作品ASIN | `B08P5KMDVX` | 43 B の透明GIF |
| 映像作品ASIN | `B07Q9MJDW1` | 43 B の透明GIF |
| 映像作品ASIN | `B00005R24T` | 43 B の透明GIF |

**自動導出できるのは本・漫画だけです。** 映画・アニメ・ドラマは商品ページの画像URL
(`images/I/<画像ID>...`)を手で貼る経路が必要になります。

### 補足: 代替の入手元は現時点で使えませんでした

日本語書籍向けのopenBD(`cover.openbd.jp/<ISBN13>.jpg`)も試しましたが、
検証した3つのISBNすべてで404でした。今回はAmazonの画像URLで進めます。

## PR-1: CSPの緩和・保存API・表示

### 変更1: CSPにAmazonの画像ホストだけを追加する

`src/http.ts` の `img-src` にホストを2つ足します。**ワイルドカード(`https:`)にはしません。**

```
"img-src 'self' data: https://m.media-amazon.com https://images-na.ssl-images-amazon.com",
```

`script-src` は触りません(既存テスト `test/production.test.js:88` が `script-src` を検証していますが、
`img-src` を検証しているテストは無いため、この変更で既存テストは壊れません)。

**画像をWorkerで中継(プロキシ)する案は採りません。** 同一オリジンにできてCSPを触らずに済みますが、
リクエスト数とコードが増えます。直リンクで足りるうちは足りる方を選びます。

### 変更2: 保存API `PATCH /api/works/:id/cover`

`src/routes/work-preference-v131.ts` と同じ「読み取り→1キーだけ差し替え→書き戻し」の形にします。

**既存の `PATCH /api/works/:id` を使わない理由**: あちらは `metadata` を丸ごと置き換えるため
(`works.ts:253`)、クライアントが表紙だけ送ると `ai_facts` を消してしまいます。
サーバー側でマージする専用の入り口を作るほうが安全です。

保存時の検証:

- `https:` のみ許可する
- ホストは CSP と同じ2つに限定する(CSPで弾かれるURLを保存させない)
- 文字数の上限を設ける
- サイズ指定を正規化する(下記)

### 変更3: 保存時にサイズ指定を正規化する

前提2のとおり、ここが軽さの本体です。用途ごとに使い分けます。

| 用途 | サイズ指定 | 実測 |
| --- | --- | --- |
| 一覧カードのサムネイル | `THUMBZZZ` | 2.1KB |
| 詳細パネル | `MZZZZZZZ` | 6.3KB |

保存するのは元URL1本だけにして、表示時にサイズ指定の部分を差し替えます。
`LZZZZZZZ` は使いません(1枚42KB)。

### 変更4: 表示

**一覧カード**: `.work-card-main` の中に左側サムネイルとして置きます。

```html
<img class="cover-thumb" src="…THUMBZZZ.jpg" alt="" loading="lazy" decoding="async" width="48" height="68">
```

- `loading="lazy"` と `decoding="async"` を必ず付けます
- `width`/`height` を明示し、読み込み前後でカードの高さが動かないようにします
- `alt=""` にします(装飾であり、隣にタイトルの文字があるため)

**空画像(43バイトGIF)への対応**: 前提3のとおり `onerror` は使えません。
読み込み後に `naturalWidth <= 1` なら、画像を隠して既存の見た目に戻します。

**注意**: カードに画像を足すと高さが変わる可能性があります。前回入れた
`contain-intrinsic-size: auto 320px`(`public/styles/app.css`)は実測値に基づく指定のため、
**実装後に高さを測り直して更新してください。** ずれるとスクロールバーが不正確になります。

### 確認方法

1. 表紙を登録した作品の一覧カードに画像が出ること
2. 開発者ツールのネットワークで、画面外のカードの画像が読み込まれていないこと
   (`loading="lazy"` と `content-visibility:auto` の併用が効いていること)
3. 表紙が無いISBNを登録したとき、透明な隙間ではなく元の見た目に戻ること
4. CSPエラーがコンソールに出ないこと
5. 一覧のスクロールが最下部まで破綻しないこと(`contain-intrinsic-size` の再測定後)

## PR-2: 登録のしやすさ

### 経路1: 本・漫画はISBNから自動(入力ゼロ)

`metadata.ai_facts.work.isbn_10` が既にある作品は、URLを組み立てるだけで表紙が付きます。
**利用者の入力は不要です。**

`isbn_13` しか無い場合に備えて、ISBN-13→ISBN-10の変換を入れます
(先頭の `978` を外し、チェックディジットを計算し直すだけ。10行程度)。

**着手前に確認したいこと**: 手元の開発用データにはISBNを持つ作品が1件もありませんでした。
本番で `ai_facts.work.isbn_10` / `isbn_13` を持つ作品が何件あるかで、この経路の価値が決まります。
少ないようなら、AI事実補完を先に回す運用のほうが早いかもしれません。

### 経路2: それ以外はURL貼り付け

詳細パネルに入力欄を1つ置き、次のどれを貼っても通るようにします。

| 貼られるもの | 扱い |
| --- | --- |
| 画像URL(`images/I/…`) | サイズ指定部分を正規化して保存 |
| 画像URL(`images/P/…`) | 同上 |
| 商品ページURL(`/dp/<ASIN>`) | ASINを取り出す。本ならISBN-10として使える |

商品ページURLから取り出したASINが本以外だった場合、前提4のとおり透明GIFになります。
その場で1回読み込んで `naturalWidth <= 1` を判定し、
「この商品は自動で取得できません。商品ページで画像を右クリックして画像URLを貼ってください」と案内します。

### 確認方法

1. ISBNを持つ本に、操作なしで表紙が付くこと
2. `isbn_13` しか無い作品でも表紙が付くこと(変換の確認)
3. 画像URLを貼って保存できること
4. 商品ページURLを貼って、本なら表紙が付くこと
5. 映画の商品ページURLを貼ったとき、黙って空にならず案内が出ること
6. 不正なURL(`http:`、別ホスト)が保存を拒否されること

## 実装順序

1. **PR-1**。CSPを緩めない限り何も見えないため、必ず先です
2. **PR-2**。PR-1で表示できる状態にしてから、登録経路を足します

## 要判断事項

1. **Amazonの画像を直リンクする点について。** Amazonの画像はProduct Advertising APIの規約上、
   アソシエイト向けに提供されているものです。個人の記録用として直リンクする前提で進めてよいか、
   確認させてください。進めるなら計画どおり実装します。
2. **表紙を一覧に出すか、詳細だけにするか。** 軽さを最優先するなら詳細だけが最軽量です。
   既定案は「一覧はサムネイル(2.1KB)、詳細は中サイズ(6.3KB)」です。
3. **映画・アニメ・ドラマは手貼りのみで許容するか。** 前提4のとおり自動化できません。
